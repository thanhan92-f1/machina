The Problem

Why enterprises need unified hypervisor host operations.

⌨

Manual CLI Complexity

Managing QEMU/KVM guests through libvirt and virsh requires memorizing dozens of commands, XML snippets, and flags. New team members face a steep learning curve that slows onboarding and increases error rates.

🔍

No Unified Dashboard

Without a central management interface, operators must SSH into each host, run separate tools for VMs, networks, and storage, and piece together system state from scattered CLI outputs.

⚠

Security Blind Spots

Ad-hoc scripts and direct libvirt access lack audit trails, input validation, and access controls. No RBAC, no API tokens, no structured logging of who did what and when.

⚙

No Automation

Backup, snapshot scheduling, batch operations, and monitoring require custom scripting. Each team builds their own tooling, creating maintenance burden and inconsistent practices.

"Operations teams spend 40% of their time on manual VM lifecycle tasks that should be automated. The operational overhead of managing KVM without proper tooling is unsustainable at scale."

Security

Defense-in-depth from authentication to input validation.

Authentication

  • PAM authentication (system users)
  • API token support for automation
  • Session management
  • Same-origin policy (no CORS)

Authorization

  • Role-based access control (RBAC)
  • Per-endpoint permission checks
  • Audit logging for all operations
  • Structured tracing output

Input Validation

  • VM name, vCPU, memory validation
  • XML escaping on all user inputs
  • Integer overflow protection (checked_mul)
  • Disk capacity bounds (0-10240 GB)

SSRF Prevention

  • Migration URI allowlist enforcement
  • Only qemu://, qemu+ssh://, qemu+tcp://, qemu+tls://, qemu+unix:// allowed
  • Blocks arbitrary network connections

Path Security

  • ISO path: canonicalize() + is_file()
  • PTY path: must start with /dev/pts/
  • Backup ID: digits and dashes only
  • Prevents path traversal attacks

Systemd Hardening

  • ProtectSystem=strict
  • NoNewPrivileges=true
  • ReadWritePaths for /dev/pts only
  • Minimal privilege execution
"machina applies security at every layer: authentication, authorization, input validation, path canonicalization, SSRF prevention, and systemd sandboxing. No shortcuts."

Deployment

One-command install on any major Linux distribution.

# Automated install (Fedora, RHEL, Ubuntu, Debian, openSUSE, Arch)
sudo ./install.sh

# Or build manually
make all                  # Release build + web frontend
sudo make deploy          # Install + start systemd service

# Remote hypervisor: rsync sources + build on server (see scripts/deploy-remote.sh)
# ./scripts/deploy-remote.sh USER@HOST --bind 0.0.0.0
# ./scripts/deploy-remote.sh USER@HOST --remote-check   # compile smoke after rsync

# Access
Web UI:   http://localhost:5092
TUI:      machina
API:      curl http://localhost:5092/api/vms
